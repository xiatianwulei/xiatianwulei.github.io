# 声明式 UI 速查表（Compose / ArkUI / SwiftUI）

> 跨语言开发记不住就放这儿。布局容器 + 状态修饰符对照速查。
> 鸿蒙统一用 **ArkUI 状态管理 V2**，不再记 V1。

## 一、布局容器对照

### 1.1 基础线性容器（Column / Row）

| 用途 | Android Compose | 鸿蒙 ArkUI (V2) | SwiftUI |
|------|----------------|----------------|---------|
| 纵向排列 | `Column { }` | `Column() { }` | `VStack { }` |
| 横向排列 | `Row { }` | `Row() { }` | `HStack { }` |
| 前后重叠 | `Box { }` | `Stack() { }` | `ZStack { }` |
| 自适应填充 | `Box(modifier = Modifier.fillMaxSize())` | `Column() { }.width('100%').height('100%')` | `VStack { }.frame(maxWidth: .infinity, maxHeight: .infinity)` |

**示例：纵向三个文本**

```kotlin
// Compose
Column(
    verticalArrangement = Arrangement.spacedBy(8.dp),
    horizontalAlignment = Alignment.CenterHorizontally
) {
    Text("A")
    Text("B")
    Text("C")
}
```

```typescript
// ArkUI (鸿蒙 V2)
Column({ space: 8 }) {
  Text('A')
  Text('B')
  Text('C')
}
.width('100%')
.alignItems(HorizontalAlign.Center)
```

```swift
// SwiftUI
VStack(spacing: 8) {
    Text("A")
    Text("B")
    Text("C")
}
.frame(maxWidth: .infinity)
```

### 1.2 间距 / 对齐 修饰对照

| 概念 | Compose | ArkUI (V2) | SwiftUI |
|------|---------|-----------|---------|
| 子项间距 | `Arrangement.spacedBy(8.dp)` | `Column({ space: 8 })` | `VStack(spacing: 8)` |
| 水平居中 | `Alignment.CenterHorizontally` | `.alignItems(HorizontalAlign.Center)` | `.frame(maxWidth: .infinity)` + 默认居中 |
| 垂直居中 | `Alignment.CenterVertically` | `.alignItems(VerticalAlign.Center)` | `.frame(maxHeight: .infinity)` |
| 内边距 | `Modifier.padding(16.dp)` | `.padding(16)` | `.padding(16)` |
| 外边距 | 无单独 margin，用 padding | `.margin(16)` | 无单独 margin，用 padding |

### 1.3 滚动与列表容器

| 用途 | Compose | ArkUI (V2) | SwiftUI |
|------|---------|-----------|---------|
| 纵向滚动 | `Column(Modifier.verticalScroll(rememberScrollState()))` | `Scroll() { Column(){} }` | `ScrollView { VStack {} }` |
| 横向滚动 | `Row(Modifier.horizontalScroll(...))` | `Scroll(scrollable: Axis.Horizontal)` | `ScrollView(.horizontal) { HStack {} }` |
| 数据列表 | `LazyColumn { items(list) { Item() } }` | `List({ space }) { ForEach(list) { Item() } }` 或 `LazyForEach` | `List(list) { item in Item() }` 或 `ForEach` |
| 网格 | `LazyVerticalGrid` | `Grid() { GridItem() }` | `LazyVGrid` / `Grid` |

**数据列表示例**

```kotlin
// Compose
LazyColumn {
    items(items = data) { item ->
        Text(item.name)
    }
}
```

```typescript
// ArkUI (鸿蒙 V2)
List({ space: 8 }) {
  ForEach(this.data, (item: Item) => {
    ListItem() {
      Text(item.name)
    }
  }, (item) => item.id)
}
```

```swift
// SwiftUI
List(data) { item in
    Text(item.name)
}
// 或
LazyVStack {
    ForEach(data) { item in
        Text(item.name)
    }
}
```

### 1.4 常用子视图

| 组件 | Compose | ArkUI (V2) | SwiftUI |
|------|---------|-----------|---------|
| 文本 | `Text("x")` | `Text('x')` | `Text("x")` |
| 图片 | `Image(painter)` | `Image(src)` | `Image("name")` |
| 按钮 | `Button(onClick) { Text() }` | `Button('x') { }.onClick(()=>{})` | `Button("x") { }` |
| 输入框 | `TextField(value, onValueChange)` | `TextInput({ placeholder })` | `TextField("", text: $binding)` |
| 分割线 | `Divider()` | `Divider()` | `Divider()` |

## 二、状态管理 / 修饰符对照

### 2.1 鸿蒙 `@ObservedV2` 这套（重点记，只用 V2）

ArkUI 状态管理 V2 用 `@` 装饰器，核心是「谁需要被观察就标谁」：

```typescript
@ObservedV2
class User {
  @Trace name: string = 'Tom'   // @Trace 标记需要深度追踪的字段
  @Trace age: number = 18
}

@Entry
@ComponentV2
struct Page {
  @Local user: User = new User()   // @Local 组件内部状态
  @Param title: string = ''        // @Param 接收父组件入参（单向）
  @Provider count: number = 0      // @Provider 向下提供（可跨层）
  @Consumer num: number = 0        // @Consumer 接收 @Provider

  build() {
    Column() {
      Text(this.user.name)
      Button('改名').onClick(() => { this.user.name = 'Jerry' })  // 自动刷新
    }
  }
}
```

| 装饰器 | 作用 |
|--------|------|
| `@ObservedV2` | 标记可被观察的类 |
| `@Trace` | 标记类中需追踪的字段（必须配合 V2 类，改了自动刷新 UI） |
| `@Local` | 组件内部状态，可本地修改 |
| `@Param` | 父 → 子 单向入参 |
| `@Provider` / `@Consumer` | 跨层状态共享（祖 → 孙） |
| `@Computed` | 派生计算值（类似 computed getter） |
| `@Event` | 子 → 父 回调事件 |

> 记忆口诀：**V2 = `@ObservedV2` 标类 + `@Trace` 标字段 + `@Local` 当状态**。改了 `@Trace` 字段，UI 自动刷新。

### 2.2 三家状态管理对照

| 概念 | Compose | ArkUI (V2) | SwiftUI |
|------|---------|-----------|---------|
| 组件内部可变状态 | `var state by remember { mutableStateOf(0) }` | `@Local count: number = 0` | `@State private var count = 0` |
| 状态变化触发重组 | `mutableStateOf` 自动 | `@Local` / `@Trace` 自动 | `@State` 自动 |
| 父传子（单向） | 普通函数参数 | `@Param value: number` | `let value: Int` 普通属性 |
| 父传子（双向绑定） | `rememberSaveable` + 回调 | `@Param` + `@Event` | `@Binding var value: Int` |
| 可观察对象 | `class VM : ViewModel` | `@ObservedV2 class VM` | `class VM: ObservableObject` |
| 对象里需追踪的字段 | `MutableState` / `StateFlow` | `@Trace field` | `@Published var field` |
| 视图中引用对象 | `val vm by viewModel()` | `@Local vm: VM` | `@StateObject` / `@ObservedObject var vm` |
| 派生/计算值 | `derivedStateOf { }` | `@Computed get() {}` | `var computed: Int { ... }` |
| 跨层共享 | `CompositionLocal` | `@Provider` / `@Consumer` | `EnvironmentObject` |
| 副作用 | `LaunchedEffect` / `DisposableEffect` | `aboutToAppear` / `aboutToDisappear` | `.onAppear` / `.task` |

**可观察对象示例**

```kotlin
// Compose + ViewModel
class CounterVM : ViewModel() {
    private val _count = MutableStateFlow(0)
    val count = _count.asStateFlow()
    fun inc() = _count.update { it + 1 }
}
// 视图
val count by vm.count.collectAsStateWithLifecycle()
Button(onClick = vm::inc) { Text("$count") }
```

```typescript
// ArkUI V2
@ObservedV2
class CounterVM {
  @Trace count: number = 0
  inc() { this.count++ }
}
@Entry @ComponentV2
struct Page {
  @Local vm: CounterVM = new CounterVM()
  build() {
    Column() {
      Text(`${this.vm.count}`)
      Button('+1').onClick(() => this.vm.inc())
    }
  }
}
```

```swift
// SwiftUI
class CounterVM: ObservableObject {
    @Published var count = 0
    func inc() { count += 1 }
}
struct Page: View {
    @StateObject private var vm = CounterVM()
    var body: some View {
        VStack {
            Text("\(vm.count)")
            Button("+1") { vm.inc() }
        }
    }
}
```

## 三、Compose 阅读与上手补遗（只看这一节也能写简单页面）

> 给没亲手写过 Compose、但能读懂 ArkUI / SwiftUI 的人。目标：能看懂 AI 生成的 Compose 代码，并照猫画虎写出简单页面。

### 3.1 三个必懂的"固定套路"

**① `@Composable` 注解**
所有能画在界面上的函数都得标它。看到满屏 `@Composable fun Xxx() { }`，知道"这是个 UI 组件函数"即可。

```kotlin
@Composable
fun Greeting(name: String) {
    Text("Hello $name")
}
```

**② `Modifier` 链式调用（顺序即布局先后）**
Compose 的样式全靠 `Modifier.xxx()` 串起来。**顺序不同，结果不同**：

```kotlin
// 先扩边距再上红色背景 → 红底只在文字周围
Text("Hi", Modifier.padding(8.dp).background(Color.Red))

// 先上红底再扩边距 → 红底外还有一圈空白
Text("Hi", Modifier.background(Color.Red).padding(8.dp))
```

记忆：**从左到右 = 从内到外一层层包**。这和 SwiftUI 的 `.padding().background()` 顺序语义一致。

**③ `remember {}` / `rememberSaveable {}`**
AI 写的 Compose 几乎必带。作用：**把值/对象缓存住，重组（刷新）时不丢失、不重算**。

```kotlin
// 不包 remember：每次刷新 count 都变回 0
var count = 0

// 包了 remember：刷新时保留原值（配置变更如旋屏会丢）
var count by remember { mutableStateOf(0) }

// rememberSaveable：连旋屏都不丢（存到 Bundle）
var count by rememberSaveable { mutableStateOf(0) }
```

对照你已有的知识：
- SwiftUI 的 `@State` → 自动保留，等价于 Compose 的 `remember`
- ArkUI V2 的 `@Local` → 也是自动保留

所以记住一句：**Compose 不会自动帮你留状态，得手动 `remember` 包一下**。

### 3.2 重组（Recomposition）= 刷新

Compose 改状态后重画 UI 的机制叫**重组**，对应 ArkUI 的"刷新"、SwiftUI 的"重绘"。同一个词，别被术语卡住。

### 3.3 标准业务逻辑套路（AI 最爱写的模板）

一句话流程：**VM 里 `StateFlow` 发数据 → 视图用 `collectAsStateWithLifecycle()` 收 → 收到就重组**。

```kotlin
// 1) ViewModel：用 StateFlow 持有数据
class UserVM : ViewModel() {
    private val _name = MutableStateFlow("Tom")
    val name = _name.asStateFlow()
    fun rename() = _name.update { "Jerry" }
}

// 2) 视图：收集 StateFlow，自动转成 Compose 状态
@Composable
fun UserPage(vm: UserVM = viewModel()) {
    val name by vm.name.collectAsStateWithLifecycle()  // 收到新值即重组
    Column(Modifier.padding(16.dp)) {
        Text(name)                                    // 显示当前名字
        Button(onClick = vm::rename) { Text("改名") }  // 点击触发 VM 改值
    }
}
```

看代码时顺着这条线读：`viewModel()` 拿到 VM → `collectAsStateWithLifecycle()` 订阅 → 点按钮调 VM 方法 → `StateFlow` 发新值 → 重组刷新界面。

### 3.4 照猫画虎：自己写一个简单列表页

把前面学的容器 + 列表 + 状态拼起来，这就是一个最小可运行页面：

```kotlin
data class Movie(val id: Int, val title: String)

@Composable
fun MovieListPage() {
    // 状态：电影列表（remember 保留）
    var movies by remember { mutableStateOf(listOf(Movie(1, "星际穿越"), Movie(2, "盗梦空间"))) }

    Column(Modifier.fillMaxSize().padding(16.dp)) {
        Text("电影列表", Modifier.padding(bottom = 8.dp))
        // 列表：LazyColumn + items
        LazyColumn(verticalArrangement = Arrangement.spacedBy(8.dp)) {
            items(movies) { movie ->
                Text(movie.title, Modifier
                    .fillMaxWidth()
                    .background(Color(0xFFF0F0F0))
                    .padding(12.dp))
            }
        }
        // 加一条
        Button(onClick = {
            movies = movies + Movie(movies.size + 1, "新电影${movies.size + 1}")
        }) {
            Text("添加电影")
        }
    }
}
```

要点回顾（都来自前面的章节）：
- 容器：`Column` 纵向排
- 列表：`LazyColumn` + `items(movies)`
- 状态：`remember { mutableStateOf }`，改了触发重组
- 修饰：`Modifier.fillMaxSize().padding().background()` 链式包

## 四、ArkUI（V2）阅读与上手补遗

> 给能读懂 SwiftUI / Compose、但想巩固 ArkUI V2 写法的人。目标：照着能写简单页面。

### 4.1 三个必懂的"固定套路"

**① `@Entry` + `@ComponentV2` + `build()`**
每个页面组件都得有：`@Entry` 标入口页，`@ComponentV2` 标自定义组件（V2 必须用 V2 版），`build()` 里写 UI 树。

```typescript
@Entry
@ComponentV2
struct Page {
  build() {
    Column() {
      Text('Hello')
    }
  }
}
```

**② 链式修饰符（`.xxx()` 顺序即布局先后）**
和 Compose 一样从左到右从内到外包：

```typescript
// 先扩边距再上红底
Text('Hi').padding(8).backgroundColor(Color.Red)
```

**③ `@Local` 才是状态，普通变量不是**
V2 里组件内部可变状态必须标 `@Local`，普通 `let x = 0` 改了不会刷新界面。

```typescript
@Local count: number = 0   // 改了自动刷新
// let count = 0           // 这样改了界面不动
```

对照：SwiftUI `@State`、Compose `remember`，三家都是"标一下才刷新"。

### 4.2 刷新机制

改 `@Local` / `@Trace` 字段 → 框架自动**刷新**对应 UI。和 Compose 的"重组"、SwiftUI 的"重绘"是同一件事。

### 4.3 标准业务套路（VM 模板）

流程：**`@ObservedV2` 类里 `@Trace` 字段 + `inc()` 方法 → 页面 `@Local vm = new VM()` → 点按钮调方法 → 自动刷新**。

```typescript
@ObservedV2
class UserVM {
  @Trace name: string = 'Tom'
  rename() { this.name = 'Jerry' }
}

@Entry
@ComponentV2
struct Page {
  @Local vm: UserVM = new UserVM()
  build() {
    Column() {
      Text(this.vm.name)
      Button('改名').onClick(() => this.vm.rename())
    }
  }
}
```

### 4.4 照猫画虎：自己写一个简单列表页

```typescript
class Movie {
  id: number
  title: string
  constructor(id: number, title: string) { this.id = id; this.title = title }
}

@Entry
@ComponentV2
struct MovieListPage {
  @Local movies: Movie[] = [new Movie(1, '星际穿越'), new Movie(2, '盗梦空间')]

  build() {
    Column() {
      Text('电影列表').padding(8)
      // 列表：List + ForEach
      List({ space: 8 }) {
        ForEach(this.movies, (m: Movie) => {
          ListItem() {
            Text(m.title)
              .width('100%')
              .backgroundColor('#F0F0F0')
              .padding(12)
          }
        }, (m: Movie) => m.id.toString())
      }
      .width('100%')
      .layoutWeight(1)

      Button('添加电影')
        .onClick(() => {
          const id = this.movies.length + 1
          this.movies.push(new Movie(id, `新电影${id}`))  // @Local 数组改动触发刷新
        })
    }
    .width('100%')
    .height('100%')
    .padding(16)
  }
}
```

要点回顾：
- 容器：`Column()` 纵向排
- 列表：`List` + `ForEach(this.movies, ...)`
- 状态：`@Local movies`，改了自动刷新
- 修饰：`Text(...).width().backgroundColor().padding()` 链式包

## 五、SwiftUI 阅读与上手补遗

> 给能读懂 ArkUI / Compose、但想巩固 SwiftUI 写法的人。目标：照着能写简单页面。

### 5.1 三个必懂的"固定套路"

**① `var body: some View { }`**
每个视图都是 `struct Xxx: View`，UI 写在 `body` 里，返回 `some View`。

```swift
struct Page: View {
    var body: some View {
        VStack {
            Text("Hello")
        }
    }
}
```

**② 链式修饰符（`.xxx()` 顺序即布局先后）**
和另两家一致，从左到右从内到外包：

```swift
// 先扩边距再上红底
Text("Hi").padding(8).background(Color.red)
```

**③ `@State` 才是状态，普通 `let/var` 不是**
视图内部可变状态必须标 `@State`，否则改了界面不刷新。

```swift
@State private var count = 0   // 改了自动刷新
// var count = 0               // 这样改了界面不动
```

对照：ArkUI `@Local`、Compose `remember`，三家都是"标一下才刷新"。

### 5.2 刷新机制

改 `@State` / `@Published` 字段 → 框架自动**重绘**。和 Compose 的"重组"、ArkUI 的"刷新"是同一件事。

### 5.3 标准业务套路（ObservableObject 模板）

流程：**`ObservableObject` 类里 `@Published` 字段 + `inc()` 方法 → 页面 `@StateObject var vm = VM()` → 点按钮调方法 → 自动刷新**。

```swift
class UserVM: ObservableObject {
    @Published var name = "Tom"
    func rename() { name = "Jerry" }
}

struct Page: View {
    @StateObject private var vm = UserVM()
    var body: some View {
        VStack {
            Text(vm.name)
            Button("改名") { vm.rename() }
        }
    }
}
```

### 5.4 照猫画虎：自己写一个简单列表页

```swift
struct Movie: Identifiable {
    let id = UUID()
    let title: String
}

struct MovieListPage: View {
    @State private var movies = [
        Movie(title: "星际穿越"),
        Movie(title: "盗梦空间")
    ]

    var body: some View {
        VStack(spacing: 8) {
            Text("电影列表").padding(.bottom, 8)
            // 列表：List 或 ForEach + LazyVStack
            List(movies) { movie in
                Text(movie.title)
                    .frame(maxWidth: .infinity, alignment: .leading)
                    .padding(12)
                    .background(Color(0xF0F0F0))
            }
            Button("添加电影") {
                movies.append(Movie(title: "新电影\(movies.count + 1)"))
            }
        }
        .padding(16)
    }
}
```

要点回顾：
- 容器：`VStack` 纵向排
- 列表：`List(movies)` 或 `ForEach`
- 状态：`@State private var movies`，改了自动重绘
- 修饰：`Text(...).frame().padding().background()` 链式包

## 六、生命周期对照（UIKit → 三家）

> 你是从 UIKit（`viewDidLoad` 那套）过来的，这节是你的"翻译字典"。
> 核心差异：UIKit 的页面是一个**对象**，生命周期是它的**方法**；声明式 UI 的页面是一段**声明**，生命周期是挂在声明上的**钩子**。

### 6.1 对照表

| UIKit | ArkUI (V2) | SwiftUI | Compose |
|-------|-----------|---------|---------|
| `viewDidLoad`（创建时初始化/拉数据） | `aboutToAppear()` | `.onAppear` 修饰符（每次显示都触发，严格说≈`viewWillAppear`） | `LaunchedEffect(Unit) { }`（进入组合跑一次） |
| `viewWillAppear` / `viewDidAppear` | `.onAppear(() => {})` 修饰符 | `.onAppear` | — |
| `viewWillDisappear` / `deinit`（销毁清理） | `aboutToDisappear()` | `.onDisappear` 修饰符 | `DisposableEffect(Unit) { onDispose { } }` |
| 异步任务（自动随页面取消） | `aboutToAppear` 里起 + `aboutToDisappear` 里停 | `.task { }` 修饰符（离开自动取消） | `LaunchedEffect` / `rememberCoroutineScope` |
| 导航返回/参数接收 | `@Param` 入参 | `NavigationLink` 传参 / `.onReceive` | `NavHost` 路由参数 |

### 6.2 ArkUI（最像 UIKit，直接当 viewDidLoad 用）

```typescript
@Entry
@ComponentV2
struct Page {
  @Local count: number = 0
  private timer?: number

  aboutToAppear(): void {
    // ≈ viewDidLoad：创建时拉数据、起定时器
    this.loadData()
    this.timer = setInterval(() => { /* ... */ }, 1000)
  }

  aboutToDisappear(): void {
    // ≈ deinit：销毁时清理
    if (this.timer) clearInterval(this.timer)
  }

  build() {
    Column() {
      Text(`${this.count}`)
    }
    .onAppear(() => { /* 每次显示（含从后台回来）*/ })
    .onDisappear(() => { /* 每次消失 */ })
  }
}
```

### 6.3 SwiftUI（用修饰符，不是方法）

```swift
struct Page: View {
    var body: some View {
        VStack { Text("hi") }
        .onAppear {
            // ≈ viewDidLoad：进来时拉数据（注意每次显示都会跑）
            loadData()
        }
        .onDisappear { cleanup() }   // ≈ deinit
        .task {
            // 异步任务，离开页面自动取消（比 onAppear 更适合网络请求）
            await fetchData()
        }
    }
}
```

### 6.4 Compose（用副作用函数）

```kotlin
@Composable
fun Page(vm: PageVM = viewModel()) {
    // ≈ viewDidLoad：进入组合只跑一次
    LaunchedEffect(Unit) {
        vm.loadData()
    }
    // ≈ deinit：离开时清理
    DisposableEffect(Unit) {
        onDispose { vm.cleanup() }
    }
    Column { Text("hi") }
}
```

### 6.5 给你的记忆点

- **ArkUI**：直接把 `aboutToAppear` 当 `viewDidLoad`、`aboutToDisappear` 当 `deinit`，最省心。
- **SwiftUI / Compose**：没有"对象方法式"的生命周期，而是把"进来干嘛/离开干嘛"写成**修饰符或副作用**。初学就记：
  - 进来拉数据 → SwiftUI `.onAppear` / Compose `LaunchedEffect(Unit)`
  - 离开清理 → SwiftUI `.onDisappear` / Compose `DisposableEffect` 的 `onDispose`
- **别踩的坑**：SwiftUI 的 `.onAppear` 是"每次显示都触发"（含从下个页面返回），不像 `viewDidLoad` 只跑一次。只想跑一次的逻辑，用 `.task` 或自己加个标志位。

## 七、一句话记忆点

- **容器**：Compose `Column/Row/Box`，ArkUI `Column()/Row()/Stack()`，SwiftUI `VStack/HStack/ZStack`。名字不同，思路一样。
- **列表**：Compose `LazyColumn`，ArkUI `List`+`ForEach`，SwiftUI `List`/`ForEach`。
- **状态**：三家都是「标一个装饰器/属性包装器，改了自动刷新」。
  - Compose：`mutableStateOf` / `StateFlow`
  - ArkUI V2：`@Local` + `@ObservedV2` + `@Trace`
  - SwiftUI：`@State` / `@StateObject` + `@Published`
- **双向绑定**：Compose 靠回调，ArkUI 靠 `@Param`+`@Event`，SwiftUI 靠 `@Binding`。
- **跨层共享**：Compose `CompositionLocal`，ArkUI `@Provider/@Consumer`，SwiftUI `EnvironmentObject`。
